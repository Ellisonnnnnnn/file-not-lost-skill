对话页第一次打开时没有任何消息，这一屏决定了用户「知不知道能做什么、敢不敢开始说」。下面四版都是可点的静态稿，切换页签查看，每版下方附交互与视觉说明。

现状诊断

当前冷启动页的 5 个问题
  1. 上下断档。内容从顶栏下 16px 开始、到流程行结束，输入框钉在页底，中间空出 200px 以上，视线落点与输入位置脱节。
  2. 场景卡没有抓手。编号 01/02/03 是装饰信息，三卡同高同构、无图标，用户看不出「点哪个都行」还是「必须选一个」。
  3. 两套视觉语言。场景卡是白底实线，上传入口是浅蓝虚线大框，同级却不同形态，用户不知道该先点卡还是先传文件。
  4. 流程说明太弱。「描述需求 → 确认条件 → 查看结果」只有 12px 灰色，放在最底部几乎读不到，而这恰恰是最需要建立预期的地方。
  5. 重复与误读。输入框上方又出现一次「帮我组织需求」，与上方引导行重复；示例文案直接占满输入区，容易被当成已输入内容。

A交互要点

  • 点卡即成句。点场景卡把「指标 + 周期 + 数据范围」拼成一句话写进输入框并把光标放末尾，用户从"点选"平滑过渡到"补两句"。
  • 三种能力收成一行胶囊。上传 / 组织需求 / 看格式并列，去掉虚线大框，不再和场景卡抢层级。
  • 内容垂直居中。空对话时内容在可视区中部，输入框紧跟其下 28px，不再一上一下两处落点。
  • hover 三态。边框转主色 + 上浮 1px + 右上角箭头淡入，明确"可点"。
代价：内容高度固定，窗口很矮时需要允许内部滚动（已有 overflow:auto 兜底）。

A视觉要点

  • 头像 52px、圆角 16px、浅蓝渐变 + 主色折线图标，作为整屏唯一视觉焦点。
  • 标题 22/32 半粗 N8，副文案 14/24 N6，正文最多两行。
  • 场景卡 3 等分、12px 圆角、1px N3 描边；图标 32px 圆角方块 #F0F7FF 底。
  • 卡片内加「14 天 / AR 产线」标签，把隐式条件外显，减少用户猜。
  • 底部信任条 12px N5，三项用圆点分隔，替代原来那条读不到的流程说明。

A适用与判断

  • 新用户为主、场景相对固定的工具型产品，这版最稳。
  • 改动量最小：结构与现有 welcome() 一一对应，主要是排版与样式重做。
  • 风险：场景卡只有 3 个，指标多了要加"全部场景"入口。
实现成本：低（1 个渲染函数 + 1 组样式）。

B交互要点

  • 选完即时成句。三组 chip 任意变更，下方浅蓝条实时更新，用户看到"AI 将收到什么"。
  • 两条出口。「填入对话」写进输入框继续补话；「直接开始」一步到位，适合熟练用户。
  • 必选可校验。指标未选时预览条显示「请先选择要预测的指标」，主按钮置灰。
  • 常用组合。历史高频三连作为一键填充，减少重复点选。
代价：页面变成"半个表单"，与"对话"的产品定位略有拉扯，需要强调输入框仍然可用。

B视觉要点

  • 左侧 22px 步骤圆点 + 浅蓝底，形成清晰的三段节奏，比纯卡片更容易扫读。
  • chip 选中态：主色描边 + #E6F2FF 底 + 主色文字，未选白底 N3 描边。
  • 预览条用 #F0F7FF 底 + 3px 主色左描边，变量部分加粗，一眼看出这句是怎么拼的。
  • 场景卡降级为底部虚线小卡，只做补充，不与主流程同级。

B适用与判断

  • 适合"用户会漏要素"的场景：指标、数据范围、预测周期任一缺失都要反问一轮。
  • 也可作为方案 A 里「帮我组织需求」点开的弹层，先解决不会说的问题。
  • 风险：指标/数据源一变就要维护选项，选项多于 8 个时 chip 会拥挤。
实现成本：中（需接指标目录与数据源列表，多一组状态）。

C交互要点

  • 继续 > 重来。最近三条任务置顶，带状态与「继续 / 看结果」，老用户零输入即可回到现场。
  • 数据源状态前置。已连接 MES 与 3 个文件写在这一屏，减少"数据从哪来"的疑问。
  • 四个快捷入口。新建 / 上传 / 从模板复制 / 看上次结果，覆盖冷启动的真实分支。
  • 空库降级。一条任务都没有时，这块自动退化为方案 A 的场景卡布局。
代价：依赖任务列表与数据源接口，纯静态原型需要造数据。

C视觉要点

  • 2:1 分栏，左栏列表用统一行高与分隔线，右栏 2×2 快捷卡，信息密度明显高于 A/B。
  • 状态标签沿用列表页色板：待确认=琥珀、已完成=绿、草稿=灰，跨页一致。
  • 快捷卡图标 28px 圆角方块浅蓝底，hover 描边转主色 + 轻上浮。
  • 整体左对齐，只在 greetings 处保留一句人味，不做大标题，效率优先。

C适用与判断

  • 内部工具、用户每天用多次、任务高度重复的场景最合适。
  • 对首次使用者反而增加信息量，需要配合 A 的场景卡做兜底。
  • 建议不单独做整版，而是把「最近任务」抽成 A 底部的一条横滑卡片。
实现成本：中高（数据查询 + 新布局 + 空态降级）。

D交互要点

  • 先看一遍完整流程。用一段示例对话交代"说 → 确认 → 结果"，把用户最陌生的中间那步提前演出来。
  • 一键复用。「用这个例子试试」把示例需求写进输入框，用户只需回车，或改数字。
  • 次出口。「我要自己说」只聚焦输入框，不打断想清楚的人。
  • 示例区不可交互。带「示例」标识与斜纹底，避免被误认为真实对话记录。
代价：示例要跟着产品能力更新，否则会教错；占地最大，小屏需要折叠。

D视觉要点

  • 示例区用 1px 虚线 + 极浅斜纹底，与真实消息流区分，不用气泡描边差异去凑。
  • AI 气泡内嵌条件摘要卡（三行 label/value + 底部待确认提示），直接展示确认卡的样子。
  • 用户气泡浅灰 #F2F4F8、AI 气泡白底细边框，圆角 12px、左上角 4px，与正式消息流同构。
  • 主按钮实心主色胶囊，次按钮描边胶囊，位于示例下方居中。

D适用与判断

  • 最解决"不知道能问到什么粒度"的问题，适合对话式 AI 的新手引导。
  • 与 A 不是互斥：可把 D 缩成 A 中「看个例子」后的浮层，两行对话即可。
  • 风险：示例太具体会被当成唯一用法，需要保留"也可以说别的"的提示。
实现成本：低（纯静态内容 + 一次填充动作）。

我的建议

单看四版，A 做默认首屏最稳，B 补"不会说"，C 补"懒得说"，D 补"不敢说"。真正上线建议是组合，而不是四选一。

主线：A默认首屏用 A 的居中式布局，解决上下断档与视觉层级问题，改动最小、风险最低。
叠加：A 底部一行「最近任务」取 C 的前两条，横向卡片放在场景卡下方，老用户不用重述。
弹层：B点「帮我组织需求」时打开 B 的填空面板，填完回填输入框，不占首屏。
折叠：D「看个例子」以浮层展示两轮对话，替代整块示例区。
