「确认预测条件」卡片 · 四版信息精简方案

同一张卡片、同一组默认值，只改信息层级与控件组织。四个方案都保留全部可填项，区别在于「哪些先说、哪些收起来、哪些不再重复一遍」。

现在这张卡片为什么显得乱（实测 772 × 818px，其中 200px 是重复信息）
  1. 顶部蓝提示条 95px 说「不确定怎么填？每项旁边 ⓘ 有例子。第一次可先预测 7 天」，可下面默认值本来就是 7 天 / 90%，那行「采用推荐预测设置」点下去等于什么都没变。
  2. 七个字段各挂一个 ⓘ，740px 宽里出现七次同形状小圆点，形成视觉噪声，真正需要解释的只有三个。
  3. 「指标口径 SUM(QTY, GRADE ∈ [A,T,Q])」独占 42px 蓝底条，它是数据源的派生信息，却被抬成和预测指标同级的一块。
  4. 底部确认语句 63px，把上面刚填的起止日期、指标名、天数原样再念一遍。
  5. 七项排四行，最后一行只有左边「关注线」一格，右边留白；「预测未来」和「预测区间」本是同一件事（怎么预测），被拆成两个并列字段。
  6. 「本轮分析数据」切换和「数据源与口径版本」下拉是两级选择，中间没有层级提示，看起来像两个无关的控件。
方案 C · 分组重排 按「预测目标 / 数据设置」分两段 字段 7 → 3 行 · 高度约 552px
做了什么
  • 分两段：预测目标（指标 / 产品 / 关注线，三列一行）、数据设置（数据源 / 历史区间 / 预测设置）
  • 历史起止合并成一个区间控件，预测天数与区间合并成一个复合控件
  • 说明只留在需要交代口径的地方（历史区间、预测设置、更多数据条件），其余字段不写灰字
  • 七项从四行压到三行，没有空格
代价
  • 复合控件要新做，日期区间和「天数 + 区间」都是新组件
  • 口径说明只在三处出现，其余字段的取数规则要回到数据源描述里找
  • 三列在 772px 下每列 236px，长产品名会被截断
方案 B · 摘要优先 默认只看结论，要改才展开 默认高度约 270px · 展开后 610px
做了什么
  • 顶部三行摘要：预测对象 / 数据范围 / 预测设置，一眼读完本轮到底要算什么
  • 表单默认收起，点「修改条件」才展开，展开后仍是两列七项
  • footer 只留两个按钮，不再重复已经写在摘要里的数字
代价
  • 第一次使用的人看不到有哪些可调项，容易直接点确认
  • 多一次点击才能改任何一项
  • 摘要里的值会变，需要保证与表单严格同步
方案 A · 精简去重 不动结构，只删重复内容 字段 7 · 图标 3 · 说明块 1 · 高度约 600px
做了什么
  • 蓝提示条改为标题右侧一行「恢复推荐设置 7 天 / 90%」，只在改动过才需要点
  • 指标口径并入数据源下方一行灰字，不再是独立色块
  • ⓘ 从 7 个减到 3 个：数据源、预测指标、关注线；其余靠 placeholder 举例
  • 底部确认语句压成 footer 左侧一行「07-01 ~ 11-10 · 未来 7 天」
  • 关注线跨整行，右端标出单位，不留半行空位
代价
  • 四个字段失去字段级说明，只在 placeholder 里给一个例子
  • 「更多数据条件」仍是一个纯文字折叠，发现性一般
  • 结构没变，两列四行的节奏还在，只是变轻
方案 D · 推荐 / 自定义 新手走三个决策，老手开全量 推荐态 3 项 · 高度约 280px
做了什么
  • 标题右侧一个两档开关：推荐设置 / 自定义
  • 推荐态只问三件事：预测指标、产品范围、预测几天（天数用胶囊，1 / 7 / 14 / 30）
  • 其余四项以一行只读文字交代「90% 区间 · 近 90 天 · 无关注线 · 平台数据源 v1」
  • 切到自定义态才出现完整七项与「更多数据条件」
代价
  • 需要记住用户上次用的模式，否则老手每次都要多切一刀
  • 推荐态隐藏了数据源版本，出问题时不好追责
  • 两套布局要分别维护
如果只选一个

选 方案 A。它删掉的正是那六条诊断里的内容，改动集中在一个渲染函数和几行样式，不新增任何组件，风险最低；卡片从 818px 降到约 600px，还顺手补掉了「关注线右边空一格」。

如果还能再往前走一步，把 C 的两段分组叠加上去：A 负责删重复，C 负责把剩下的按语义排成两段、把四行压成三行。两者不冲突，合起来是最终形态。B 更适合「这张卡会被反复看、但很少改」的场景；D 适合产品里有明确的新手与熟练用户分层。
