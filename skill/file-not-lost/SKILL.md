# 文件不迷路

一句话：把项目里散落的产出，整合成**一张持续维护的 HTML 文件地图**。用户不需要写一行代码。

## 给 AI 的说明

### 要解决的问题

同一条需求会改出 v1…v6、导出十几个 HTML 和截图，全散在一个目录里。半年后用户记得「我做过那个抽屉」，但认不出哪份是最新、哪份解决了什么问题。

你的活是把它们变成一张能一眼扫完的图：**谁是最新、谁是谁的旧版、每一份解决了什么**。找文件从「翻目录」变成「扫一眼」。

### 产物

一个单文件、零依赖、双击 `file://` 就能开的 HTML。卡片即文件，多版本的卡点开是扇形展开的历史版本，可删除、可撤回（只是展示态，不动磁盘）。

样式已经是成品，**你的产出是数据，不是页面**。

### 三个前提

1. **样式固定，数据生成。** `assets/index-template.html` 里的 CSS 与交互逻辑是成品，任何一次调用都不重写、不微调。你只负责产出一份 `map.json`，注入进去。
2. **是同一张图，不是每次新建。** 第二次要改的是 `map.json`，页面壳、指纹、样式一律不动。重新生成会把用户手写的一句话说明、手动归的组、刻意删掉的卡全部冲掉——这是这套东西最容易毁掉的地方。
3. **分区跟着角色走，不跟着文件类型走。** 设计师 5 区（主稿 / 产品原型 / 模块方案 / 迭代轨迹 / 其他）、PM 4 区（需求范围 / 流程状态 / 方案对比 / 口径验收）。判区看「这份文件在流程里干什么」，不看扩展名。见 `references/taxonomy-*.md`。

### 行为准则（细则见文末「硬规则」）

- **先查现状再动手。** 目标在不在图里、在哪一区，决定这句话是「加卡」「更新」还是「移动」。
- **能推断就不问。** 反问只留三种（见下节），其余先做，做完把判断写出来。
- **不编造。** 没扫到的文件不写；空区留空；说明写「解决了什么问题」，不写「包含什么」。
- **不动用户的磁盘。** 页面上的删除是内存态，不删文件。
- **不碰样式。** 要改视觉 = 规格变更：改壳 → `rehash_shell.py` → 重建所有用这张壳的页。

### 一次调用的动线

`定位目录 → 判角色 → 查重（在不在图里、在哪一区） → 动手（加卡 / 更新 / 移动 / 新建） → 写 map.json → 构建 → 自检 → 打开看一眼`

### 什么算做完

六项自检全过，**并且**你亲眼看过页面：卡片排布、扇形展开、空区显示。静态检查全绿但视觉错位是发生过的。

## 一句话指令怎么落地

用户的指令往往很短，比如「主稿的索引加入文件地图里」。**默认假设他是在改现有那张图，不是要新建一张。** 动手前先查一次现状：

```bash
# 看目标文件在不在图里（按 href 匹配，别按卡片名猜）
grep -o '"href": "\./[^"]*"' 文件地图.html | sort -u
```

四种情况四种处理：

| 现状 | 处理 |
| --- | --- |
| 目标文件**已在图里** | 不新建卡、不反问。按「更新这张卡」做：核对 href 可达、日期体积是否最新、`note` 是否还成立，做完回述「它原本在 01 主稿，我更新了 X」 |
| 目标文件**不在图里** | 按分类轴归区加卡，直接做 |
| 目标文件**在别的区**（用户说「加进主稿」） | 移进目标区，版本链原样带走，原位置不保留重复卡，回述移了哪张 |
| 指令和现状**看起来矛盾** | 先按"更新"做一步，把发现写在回复里（「它已经在 01 主稿，链接是 ./x.html；如果你是要换成别的文件，说一声」）。**不要**用一句「你具体指什么」把球踢回去 |

只有三种情况值得反问，其余先做再说：

1. **同族候选要不要合成一张卡**——合错比拆错代价大。
2. **文件消失了**——是改名还是真删。
3. **角色不明**——设计师 / PM 两套分类轴，落错区整页都要重排。

「索引」「主稿」「加进去」这类词在用户语言里是模糊的，但在本 skill 的语汇里都有确定含义：主稿 = 01 区 `lead` 的 `item`，加进去 = 出现在 `map.json` 的某张卡里。**先用 skill 的语汇解释，解释不通再问。**

## 流程

### 0. 定位目录

用户很少会贴绝对路径（每次对话的工作区都不一样），**不要因为缺路径就反问**。按顺序判断，命中即停：

1. 用户明确给了路径或目录名 → 直接用。
2. 工作区里已经有一张文件地图（`**/文件地图.html` 或 `*-产出索引*.html`）→ 那是同一个项目，走「维护已有地图」，不是新建。
3. 工作区下只有一个明显的产出目录（如 `downloads/<项目名>/`，或根目录下唯一的业务文件夹）→ 直接用它。
4. 有多个候选 → 只问一句，把候选按最近修改时间列出来让用户挑，不要逐个试探扫描。

选定后**开头回述一句**「按 `<目录>` 建图 / 更新」，用户能一眼看出有没有认错，不必先问。

路径只影响扫描范围，不影响后续所有步骤；`map.json` 与页面输出都落在该目录内，不要写到工作区根目录。

### 1. 扫描

```bash
python3 scripts/scan_files.py <项目目录> -o candidates.json --include-thumbs
```

它会排除噪声（临时文件、`.git`、`node_modules`、zip）、算好日期与体积、标出哪些是快照、并把「剥掉日期和版本号后同名」的文件归成疑似同族。

**打不开的伴生文件默认不进图**：`.css` `.js` `.jsx` `.ts` `.scss` `.yml` 这类，双击只能看到源码，不是可交付物。它们是被排除的，清单写在 `candidates.json` 的 `sidecar` 里；确实需要收进来时加 `--keep-scripts`。

**同族候选要拿给人确认。** 脚本给的是候选不是结论，合错比拆错代价大。

### 2. 归类

先判角色，再落区：

- 用户是这个项目的设计师 → `references/taxonomy-designer.md`
- 用户是产品经理 → `references/taxonomy-pm.md`

没有明确信号时问一句，别猜。判区看「这份文件在流程里干什么」，不看扩展名。

归组细节（什么进版本链、什么进轨迹、同族怎么判）见 `references/grouping.md`。

**某区确实没有文件时，保留这个区，内容留空。** 分区是稳定骨架，不是「有多少填多少」的容器；缺内容就空着，页面显示「暂无内容」。空着比填错好，也比整区消失好——用户下次看到 01 没了会以为页面出错。

### 3. 写 map.json

严格按 `references/map-schema.md`。三条最容易错的：

- `versions[0]` 必须是**当前版本**——主图、底栏、单版本直达链接都用它
- `name` ≤ 12 字，`note` ≤ 30 字，超了会被截断成省略号（字数预算见 `references/copy-rules.md`）
- 卡片 `id` 全局唯一，浮层靠它反查

### 4. 构建

```bash
python3 scripts/build_map.py map.json <输出目录>/文件地图.html
```

脚本会先校验壳指纹与数据契约。壳被手改过、字段缺失、`tone` 非法，都直接拒绝构建，不产出半个页面。

### 5. 自检

```bash
python3 scripts/check_page.py <输出目录>/文件地图.html
```

六项全过才交付：壳指纹、注入属性、MAP 可解析、数据契约与卡号唯一、标题元信息、链接可达、体积。

**交付前必须真的打开看一眼**（浏览器或预览面板），确认卡片排布、缩略图、扇形展开正常。静态检查通过但视觉错位是有的。

## 维护已有地图

```bash
python3 scripts/scan_files.py <目录> -o candidates.json --include-thumbs
python3 scripts/merge_map.py map.json candidates.json -o merge-report.md --ignore "*.png"
```

报告分四类：未变 / 变更 / 消失 / 新增。按它改 `map.json`，只动该动的地方：

| 情况 | 动作 |
| --- | --- |
| 变更 | 只更新 `size` 和 `date`，**保留 note** |
| 新增 | 能并进已有卡的进 `versions`（放最前），其余按区归类 |
| 消失 | 别直接删卡。先确认是改名还是真删；真删按页面的软删语义处理 |
| 未变 | 不动 |

`note` 是人写的一句话说明，机器永远不覆盖它。

`--ignore` 用来滤掉不该进图的文件（设计稿的 PNG 截图、页面自身、临时导出），可重复。体积比较有 2% 容差、日期只比 `MM-DD`——页面存的是四舍五入后的展示值，逐字节比对会把每个文件都报成变更。

如果报告里大面积出现「日期 A→B」，先看是不是口径问题：图里的 `date` 是人标的日期，脚本取的是文件名里的日期。这类差异可以不改。

## 升级样式壳

只有在**确实需要改视觉或交互**时才碰 `assets/index-template.html`，改完必须重算指纹：

```bash
python3 scripts/rehash_shell.py          # 重算并写回头部注释
python3 scripts/rehash_shell.py --check  # 只比对
```

顺序是：改壳 → 重算指纹 → 重新构建所有用这张壳产出的地图。忘掉这一步，`build_map.py` 会以「壳被改动」为由拒绝构建，这是故意的。

改完必须在真实项目上重建一次，肉眼过三处：卡片排布、扇形展开、删除确认。自检全绿但视觉错位是发生过的。

## 硬规则

1. **不改 CSS、不改交互逻辑。** 需要改样式说明规格要升级，那是改模板 + 更新指纹，不是就地微调。
2. **不删用户的文件。** 页面上的删除只是展示态（内存），没有真实删除磁盘文件的动作。
3. **快照不进主图卡片。** 几十份「改动前」快照只进 03 轨迹区，默认收起。
4. **一个部件一张卡。** 同一部件的 A/B/C/D 方案是这张卡的版本，不是四张卡。
5. **一句话说明必须说「解决了什么」，不是「包含什么」。** 见 `copy-rules.md` 对照表。
6. **交付前清掉预览面板注入的 `data-page-node-id`。** 构建脚本已处理，但如果事后用编辑器保存过，要再跑一次 `check_page.py`。
7. **空区就留空，不许凑。** 某区没有文件：`grid` 写 `"items": []`、`timeline` 写 `"days": []`、`subgroups` 写 `"groups": []`、`lead` 不写 `item`，页面统一显示「暂无内容」。禁止的四种凑法：塞「待补充」占位卡、编一份示例文件、把别的区的文件挪过来、替空卡编一句说明。`count` 也一并省略，不要写 `0`。
8. **数据里没出现过的文件、没读过的文件，不写进图。** 卡片必须对应磁盘上真实存在的路径；`scan_files.py` 没扫到的东西，不靠印象补。
9. **只收能单独打开的文件。** 卡的每一版双击都要能看到内容：`html` / `pdf` / 图片 / `csv` / `txt` / `md`。脚本、样式、构建配置不进卡片——它们属于主稿的一部分，要交代就写进 01 的 `side.body` 一句话（「主稿由 3 个脚本拼成」），不要为它们建空壳卡。

## 文件地图

file-not-lost/
  SKILL.md                      本文件：流程与硬规则
  assets/index-template.html    样式壳（CSS + 渲染器 + 浮层交互 + 指纹）

  scripts/check_page.py         交付前六项自检

  references/
    map-schema.md               数据契约，写 map.json 前必读
    taxonomy-designer.md        设计师五区 + 卡片元信息

```
用户：把这个项目的产出整理成文件地图

0. 工作区只有一个产出目录 downloads/智能数据预测/ → 回述「按它建图」，不反问
1. scan_files.py 扫描 → 51 个文件，其中 37 份快照，疑似同族 4 组
2. 同族候选给人确认：「核对数据抽屉」4 个文件合成一张卡
3. 判角色 = 设计师，落五区：主稿 1 / 原型 0（项目没给原型稿，空区）/ 模块方案 6 / 轨迹 37 / 其他 10

```

第二次来同一目录时，走「维护」那两步，而不是从头再做一遍。
