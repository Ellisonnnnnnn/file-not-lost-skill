# 文案规范

这套图的文字都有固定位置和固定长度，超了就截断。**字数是硬约束，风格是简约、专业、商务。**

## 字数预算

| 位置 | 上限 | 超了会怎样 |
| --- | --- | --- |
| `meta.project` | 12 字 | 标题一行放不下，括号挤到第二行 |
| `meta.sub` | 两行（约 60 字） | 顶栏变高，首屏看不到 01 区 |
| 区 `title` | 6 字 | 锚点导航里换行 |
| 区 `desc` | 60 字 | 三行以上，与卡片脱节 |
| 卡片 `name` | 12 字 | 底栏省略号 |
| 卡片 `status` | 7 字 | 标签挤压名称 |
| 卡片 `note` | 30 字 | 两行截断（`-webkit-line-clamp:2`） |
| 版本 `note` | 40 字 | 清单里两行截断 |
| `timeline` 天 `body` | 100 字 | 与右侧快照标签失衡 |

## note 写什么

写**这份文件解决的问题或做出的决定**，不写内容目录。

| 别这样写 | 这样写 |
| --- | --- |
| 「包含 A/B/C/D 四版方案」 | 「四版迭代到滑选分界线形态，待合并回主稿」 |
| 「这是一个 HTML 文件」 | 「索引区固定，特征区与目标区共用可滑动分界线」 |
| 「设计稿最新版本」 | 「条件卡落方案 C：分组重排，减少一次滚动」 |

判断标准：**读完这句，能不能知道「要不要点开它」。** 不能就是废话。

## 状态词表

各角色固定词表，不自创近义词（自创会让用户怀疑是两种不同的状态）：

- 设计师：`已落地` `待合并` `未定稿` `进行中` `外部输入` `已归档`
- 产品经理：`草稿` `评审中` `已确认` `待决策` `已冻结`

## 禁止

- 不加 emoji
- 不写「点击下方卡片即可查看」这类操作说明——界面自己会说话
- 不写口号、价值主张、引导语（「让你事半功倍」「一站式管理」）
- 不在 `sub` 里解释「为什么要做这个页面」
- 不用「我们」「大家」这类主语
- 不写「更多精彩内容敬请期待」

## `sub` 的固定结构

```
时间区间　·　N 个产出文件（X MB）　·　M 份快照（Y MB）　·　另 K 项输入与参考
<br>一句话说明这套图怎么读
```

第二行只说一件事：这套图的独特点（例如「文件卡片统一为层叠 2：最新版是唯一实体卡，点开旧版沿弧线扇形展开」）。不要再往第二行塞第二件事。

## 大小与日期

- 体积：`4.8 KB` `1.09 MB` `2.27 MB`，一位或两位小数，不写 `1093 KB` 这种
- 日期：`11-25`（卡片、扇形、轨迹统一），完整日期只出现在 `sub` 的时间区间里
- 版本号：`v1` `v4` `v12`，小写 v，不补零
