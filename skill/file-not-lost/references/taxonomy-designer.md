# 分类轴 · 设计师（现行）

`role: designer` 时用这一套。四个区不是文件类型，是设计师的工作流四段：**交付 → 试方案 → 留演进 → 归档素材**。判区看「这份文件在流程里干什么」，不看扩展名。

## 01 设计主稿 · `type: lead`

**判据**：整份需求只有一个文件在持续演进，所有迭代最后都合并回它。双击就能看完整交互。

| 情况 | 处理 |
| --- | --- |
| 有唯一主稿 | 放 `lead`，右侧说明写「这一个文件里有什么」 |
| 主稿有两份（如 PC / 移动） | 拆成两个 `lead` 区，或并成一张卡的两个版本链 |
| 项目还在早期、没有收敛出主稿 | 跳过此区，01 让给「探索稿」，`no` 顺延 |

右侧说明四件套：`title`（这文件里有什么）、`body`（3–5 个模块名，用顿号）、`tags`（3–4 个，含体积）、`path`（仓库内相对路径）。

## 02 模块方案优化 · `type: grid`

**判据**：针对主稿里**某一个部件**做的多版对比稿。特征是一份文件里并排放 2–4 个方案（A/B/C/D），或同一部件迭代了多轮。

典型：抽屉、弹窗、卡片、空状态、引导页、结果页。

- 一个部件 = 一张卡，这些方案稿进 `versions`
- 只有一个方案稿也是合法的卡（单版本），只是不显示纸片层
- 只有一个稿但改过三版 → 三版进同一张卡的 `versions`，不要拆成三张卡

**不要**放进来的：整体改版（那是新主稿）、纯样式 token 调整（那是 04 的脚本或说明）。

## 03 版本迭代轨迹 · `type: timeline`

**判据**：每次大改前自动存的「改动前」快照，只用于回溯对比，不进主图卡片。

- 默认 `collapsible: true`，一进来是收起的，避免把页面拉长
- 按天分组：`date` 用 `MM-DD`，`label` 写「N 份 · 阶段名」
- 每份快照只给标题 + 体积，不给说明——它自己就是页面
- 当前主稿在最后一天里加 `now: true` 标一下
- 没有快照目录就**不要这个区**，`no` 顺延，别留空壳

## 04 其他文件 · `type: subgroups`

**判据**：既不并进主稿、也不属于某个部件的产出。默认分三组：

| 子组 | `id` | 装什么 |
| --- | --- | --- |
| 测试数据 | `g4a` | 跑通链路的样例 CSV / TXT / JSON |
| 需求输入 | `g4b` | 需求方给的原型、交互说明、字段口径 |
| 参考与中间产物 | `g4c` | 在线参考、样式参照、构建脚本、静态兜底页 |

组数可以增减，`id` 依次 `g4a` `g4b` `g4c`。

## 卡片元信息（设计师版）

| 位置 | 写什么 | 例 |
| --- | --- | --- |
| `status` | 这份稿的决策状态 | `方案 C 已落地` `四版未定稿` `最新版待合并` |
| `tone` | 状态色 | 已落地 `green`、待合并 `green`、未定稿 `gray`、外部输入 `gray` |
| `note` | 这卡解决的**问题**，不是内容目录 | 「四版迭代到滑选分界线形态」 |
| 版本 `note` | 这一版相对上一版**改了什么** | 「索引区固定，特征区与目标区共用可滑动分界线」 |

状态词表固定六个：`已落地` `待合并` `未定稿` `进行中` `外部输入` `已归档`。不要自创近义词。

## 排序

- 区内卡片：**先按状态（待合并 > 未定稿 > 已落地）**，再按最近修改倒序
- 版本链：严格按时间倒序，`versions[0]` 是当前版
- 子组：测试数据 → 需求输入 → 参考与中间产物（跟着使用频率走）
