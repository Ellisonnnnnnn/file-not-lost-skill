# 分类轴 · 设计师（现行）

`role: designer` 时用这一套。五个区不是文件类型，是设计师围绕一份交付的五件事：**交付本身 → 它的依据 → 试过的方案 → 留下的演进 → 归档的素材**。判区看「这份文件在流程里干什么」，不看扩展名。

## 01 设计主稿 · `type: lead`

**判据**：整份需求只有一个文件在持续演进，所有迭代最后都合并回它。双击就能看完整交互。

| 情况 | 处理 |
| --- | --- |
| 有唯一主稿 | 放 `lead`，右侧说明写「这一个文件里有什么」 |
| 主稿有两份（如 PC / 移动） | 拆成两个 `lead` 区，或并成一张卡的两个版本链 |
| 项目还在早期、没有收敛出主稿 | 保留 01 区、不写 `item`，页面显示「暂无内容」；右侧说明照写 |

右侧说明四件套：`title`（这文件里有什么）、`body`（3–5 个模块名，用顿号）、`tags`（3–4 个，含体积）、`path`（仓库内相对路径）。

## 02 产品原型 · `type: grid`

**判据**：动手设计之前拿到的「要做什么」的原始表达——产品经理给的原型 HTML、Axure / Figma 导出的原型页、线框稿，或按流程切好的一串截图。判断标准只有一条：**这是别人给的输入，不是你的产出。**

一条流程 = 一张卡，不是一张截图一张卡。两种装法：

| 载体 | `versions` 放什么 | `unit` | `name` 写什么 |
| --- | --- | --- | --- |
| 原型 HTML | 各次迭代版本，`versions[0]` 是最新 | 省略（默认「个版本」） | 流程名，如「数据核对流程」 |
| 截图集合 | 按流程先后排，`versions[0]` 放**入口页** | `张截图` | 同上，`thumb` 用入口页那张 |

- `note` 写「这条流程要解决什么」，不要写「一共 6 张图」——底栏已经显示「6 张截图」了
- 卡片 `status` 统一 `外部输入`、`tone: gray`，和你的设计稿一眼分得开
- 截图集合的扇形展开就是逐步走查：点开卡片后从入口页开始按顺序点，不要按日期排
- **不要混装**：同一张卡既有 HTML 又有截图，「点开直达」就不知道该开哪个

**不要**放进来的：自己做的设计稿（01）、基于主稿改的方案（03）、走查截图（05 参考与中间产物）。原型一旦开始被你改，它就不是原型了，那是新的设计稿。

## 03 模块方案优化 · `type: grid`

**判据**：针对主稿里**某一个部件**做的多版对比稿。特征是一份文件里并排放 2–4 个方案（A/B/C/D），或同一部件迭代了多轮。

典型：抽屉、弹窗、卡片、空状态、引导页、结果页。

- 一个部件 = 一张卡，这些方案稿进 `versions`
- 只有一个方案稿也是合法的卡（单版本），只是不显示纸片层
- 只有一个稿但改过三版 → 三版进同一张卡的 `versions`，不要拆成三张卡

**不要**放进来的：整体改版（那是新主稿）、纯样式 token 调整（那是 05 的脚本或说明）。

## 04 版本迭代轨迹 · `type: timeline`

**判据**：每次大改前自动存的「改动前」快照，只用于回溯对比，不进主图卡片。

- 默认 `collapsible: true`，一进来是收起的，避免把页面拉长
- 按天分组：`date` 用 `MM-DD`，`label` 写「N 份 · 阶段名」
- 每份快照只给标题 + 体积，不给说明——它自己就是页面
- 当前主稿在最后一天里加 `now: true` 标一下
- 没有快照就写 `"days": []`：区保留、显示「暂无内容」，**不要**拿普通文件或旧稿来填这一区

## 05 其他文件 · `type: subgroups`

**判据**：既不并进主稿、也不属于某个部件的产出，且**能单独打开**（脚本、样式、构建配置不进来，见 `map-schema.md` 的「收什么、不收什么」）。默认分三组：

| 子组 | `id` | 装什么 |
| --- | --- | --- |
| 测试数据 | `g4a` | 跑通链路的样例 CSV / TXT / JSON |
| 需求输入 | `g4b` | 需求方给的交互说明、字段口径、评审意见（原型已独立成 02 区） |
| 参考与中间产物 | `g4c` | 在线参考、样式参照、静态兜底页（构建脚本不进图） |

组数可以增减，`id` 依次 `g4a` `g4b` `g4c`（`g4*` 是历史命名，只当锚点用，不必对齐区号）。

## 卡片元信息（设计师版）

| 位置 | 写什么 | 例 |
| --- | --- | --- |
| `status` | 这份稿的决策状态 | `方案 C 已落地` `四版未定稿` `最新版待合并` |
| `tone` | 状态色 | 已落地 `green`、待合并 `green`、未定稿 `gray`、外部输入 `gray` |
| `note` | 这卡解决的**问题**，不是内容目录 | 「四版迭代到滑选分界线形态」 |
| `unit` | 版本计数单位，默认 `个版本` | 截图集合写 `张截图` |
| 版本 `note` | 这一版相对上一版**改了什么** | 「索引区固定，特征区与目标区共用可滑动分界线」 |

状态词表固定六个：`已落地` `待合并` `未定稿` `进行中` `外部输入` `已归档`。不要自创近义词。

## 排序

- 区内卡片：**先按状态（待合并 > 未定稿 > 已落地）**，再按最近修改倒序
- 版本链：严格按时间倒序，`versions[0]` 是当前版
- 子组：测试数据 → 需求输入 → 参考与中间产物（跟着使用频率走）
- 02 原型区：按**流程先后**排，不按状态排——它是阅读顺序，不是决策队列
