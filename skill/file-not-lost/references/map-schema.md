# map.json 数据契约

`build_map.py` 只认这一份数据。字段名写错、必填项缺失都会直接拒绝构建，不会产出半个页面。

## 顶层

```json
{
  "meta":     { ... },
  "sections": [ ... ]
}
```

## meta

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| `product` | ✓ | 产品名，固定 `文件不迷路` |
| `project` | ✓ | 项目名，渲染成 `文件不迷路（项目名）`，括号自动补 |
| `tag` |  | 标题右侧小标签，如 `层叠 2`、`PM 版`。不填则不显示 |
| `breadcrumb` | ✓ | 面包屑数组，末项建议写项目名 |
| `sub` | ✓ | 标题下一行摘要。允许 `<b> <strong> <br> <em>` |
| `quick` |  | 顶栏快捷按钮，最多 2 个。`icon` 可选 `go`（默认箭头）/ `sheet` |

`sub` 的写法：`日期区间　·　N 个产出文件（X MB）　·　M 份快照（Y MB）<br>一句话说明这套图怎么读`

```json
"meta": {
  "product": "文件不迷路",
  "project": "智能数据预测",
  "tag": "层叠 2",
  "breadcrumb": ["工业 AI 平台", "文件不迷路", "智能数据预测"],
  "sub": "2026-11-16 — 2026-11-20　·　12 个产出文件（2.27 MB）<br>点开卡片旧版沿弧线扇形展开",
  "quick": [
    { "label": "打开主设计稿", "href": "./设计稿.html" },
    { "label": "核对数据抽屉", "href": "./抽屉.html", "icon": "sheet" }
  ]
}
```

## sections

四个区，`type` 决定渲染方式。

| type | 用于 | 内容来源 |
| --- | --- | --- |
| `lead` | 01 主稿：左一张大卡 + 右侧说明 | `item` + `side` |
| `grid` | 02 模块方案：卡片网格 | `items` |
| `timeline` | 03 迭代轨迹：按天分组、默认收起 | `days` + `note` |
| `subgroups` | 04 其他文件：再分子组，每组一个网格 | `groups` |

公共字段：`id`（锚点，`s1`…）、`no`（`01`）、`title`、`count`、`desc`、`collapsible`（默认收起）。
`desc` 允许 `<b> <strong> <br> <em>`。

### lead

```json
{
  "id": "s1", "no": "01", "title": "设计主稿", "count": "1 个文件",
  "desc": "整份需求只维护这一个文件，所有迭代都落在它身上。",
  "type": "lead",
  "item": { 卡片，见下 },
  "side": {
    "title": "这一个文件里有什么",
    "body": "BOE 侧边导航、数据列表页、对话页、条件确认卡……",
    "tags": ["主交付", "单文件自包含", "1093 KB"],
    "path": "智能数据预测/设计稿.html"
  }
}
```

### grid

```json
{ "id": "s2", "no": "02", "title": "模块方案优化", "count": "6 个模块 · 9 份方案",
  "type": "grid", "items": [ 卡片, 卡片 ] }
```

### timeline

`s snaps` 里的 `now: true` 会给这一项加「当前」高亮。

```json
{ "id": "s3", "no": "03", "title": "版本迭代轨迹", "count": "37 份快照",
  "type": "timeline", "collapsible": true,
  "days": [
    { "date": "11-17", "label": "5 份 · 起稿",
      "body": "<b>打底阶段</b>：修白屏 → 换侧边导航 → ……",
      "snaps": [
        { "title": "静态首屏修复前", "href": "./迭代快照/x.html", "size": "792 KB" },
        { "title": "主稿（当前）", "href": "./设计稿.html", "size": "1135 KB", "now": true }
      ] }
  ],
  "note": "快照都是「改动前」的完整页面，可独立打开作为回归基线。"
}
```

### subgroups

`id` 会拼进网格容器，只用小写字母数字与短横线。

```json
{ "id": "s4", "no": "04", "title": "其他文件", "count": "10 个文件 · 3 类",
  "type": "subgroups",
  "groups": [
    { "id": "g4a", "title": "测试数据", "count": "2 个文件",
      "desc": "跑通上传 → 核对链路用的样例。",
      "items": [ 卡片 ],
      "note": "这一组可选的补充说明，渲染成蓝色提示条。" }
  ] }
```

## 卡片

```json
{
  "id": "check",
  "name": "核对数据抽屉",
  "status": "最新版待合并",
  "tone": "green",
  "unit": "份方案",
  "cap": "",
  "moreWord": "更多方案",
  "note": "四版迭代到滑选分界线形态，待合并回主稿。",
  "versions": [ 版本, 版本 ]
}
```

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| `id` | ✓ | 全局唯一，浮层靠它反查 |
| `name` | ✓ | 底栏标题，建议 ≤ 12 字，超过会省略号 |
| `status` |  | 状态标签文字，建议 ≤ 7 字。留空则不显示标签 |
| `tone` |  | 标签配色：`blue` `green` `gray` `orange` `red`，默认 `gray` |
| `unit` |  | 多版本时显示「N 份方案 / N 个版本 / N 个文件」，默认「个版本」 |
| `cap` |  | 主图角标。省略时多版本自动显示「当前 · vN」，单版本不显示 |
| `moreWord` |  | 超出 5 张后的入口卡文案，默认「更多版本」 |
| `note` |  | 卡下一行说明，一句话，建议 ≤ 30 字 |
| `versions` | ✓ | **按「新 → 旧」排序**，第 0 个就是主图与底栏展示的那个 |

## 版本

```json
{ "v": "v4", "title": "不可选列样式-20261120", "href": "./x.html",
  "date": "11-20", "size": "45.6 KB", "thumb": "不可选列样式-20261120",
  "ext": "HTML", "note": "索引区固定，特征区与目标区共用一条可滑动分界线。" }
```

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| `title` | ✓ | 主图 tooltip 与扇形卡标题 |
| `href` | ✓ | 相对 `./` 或 `https://` |
| `v` |  | 版本号，显示在扇形卡与删除确认里 |
| `date` |  | `MM-DD` |
| `size` |  | 人类可读体积 |
| `thumb` |  | `thumbs/` 下的文件名（不含扩展名、不含路径）。没有就留空走扩展名占位 |
| `ext` |  | 无缩略图时显示的大字，`HTML` `CSV` `PY` |
| `note` |  | 一句话说明，进扇形卡与全量清单 |

## 两条硬规则

1. **`versions[0]` 必须是当前版本。** 卡片主图、底栏日期大小、单版本的直达链接都用它。
2. **不要为了排版在 `name` 里加空格。** 宽度由栅格和 `gap` 控制，不靠字距凑。
